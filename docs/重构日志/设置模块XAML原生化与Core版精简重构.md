# 设置模块 XAML 原生化与 Core 版精简重构规划

## 1. 背景与技术债历史溯源
在之前的配置系统（`IConfigurationService` 合并）与 `AppStyles.xaml` 全局字典拆分及 TabContent 架构的大规模重构中，刀刃主要砍向了“基础设施层”和“领域逻辑层”。当时的视图层（特别是设置模块相关的 Panels）由于仅作为最终呈现端，且能够勉强适配重构后的新底层，为了避免陷入无限重构的泥潭，被判定为**低优先级暂留**。

但在针对“拆分 AppearanceSettingsPanel 功能”的专门审计中，暴露出设置模块存在一个严重的**系统性技术债集群**：
**绝大部分重度面板（包括 AppearanceSettingsPanel、GeneralSettingsPanel 等共 8 个面板）完全脱离了 XAML 原生渲染机制，采用逾千行高耦合的 C# 动态拼装 UI（Code-Behind DOM 刻绘法）。**

早期这样做旨在强行抹平 XAML 资源字典不支持而导致的各页面风格差异。然而时至今日，得益于近期的重构，诸多底层控件（如 `ModernButtonStyle` 等）已完全高度抽象与组件化，因此继续维持这种 C# 硬拼装不仅不再有任何“对齐风格”的收益，反而成了沉重且极易引发内存泄漏的技术包袱。

## 2. 核心业务诉求：Core 版界面极简化 (Pro技术储备)
随着产品演进，目前的 `YiboFile-Core` 版需要做深度的减法：
* **核心保留**：在 `AppearanceSettingsPanel`（外观设置）中，仅保留代表应用基调的三个必选项——**“主题设置（选择浅色/深色主题）”、“图标风格”、“UI方案（界面风格）”**。
* **无情裁撤**：诸如“完全自定义主题（生成调色板）、窗口透明度调节滑块、复杂界面动画开关、以及多达几十个变量的各类背景色/微光色/边框色的定制选择面板”，这些属于“发烧友定制”范围的高级特性将从当前视觉展示中彻底抹除，留作未来重建 **YiboFile-Pro** 版本的素材储备。

这次做减法的诉求，恰好与清理重度代码的架构目标**高度共振**。

## 3. 重构决策：方案B（设置模块全面 XAML 原生化战役）
基于项目轻量化、资源审计及严格贯彻 MVVM 的首要原则，经过讨论确认选取**最彻底的重构方案——方案B**。即不采取局部打补丁，而是发起一次批量的重写战役。

### 3.1 核心实施靶向
对饱受 C# 构建污染的以下 8 个关键面板进行彻彻底底的洗牌：
1. `AppearanceSettingsPanel` （外观设置——同时完成裁减特性核心任务）
2. `GeneralSettingsPanel` （常规设置）
3. `FileListSettingsPanel` （文件列表设置）
4. `HotkeySettingsPanel` （快捷键设置）
5. `LibrarySettingsPanel` （媒体库设置）
6. `PathSettingsPanel` （路径设置）
7. `TagManagementPanel` （标签管理面板）
8. `SearchSettingsPanel` （搜索设置）

### 3.2 实施原则与落地路径
* **完全原生化（XAML化）**：废弃 `Controller` 中所有的 `InitializeComponent` 动态创建与事件手搓绑定。重新建立 `.xaml` 视图，利用 `<StackPanel>`, `<ComboBox>` 与标准 `{Binding}` 完成双向数据流对接。
* **Code-Behind 的终极净化**：`.xaml.cs` 文件除了必须的 `DataContext` 注入与钩子注册外，不得超过 50 行代码。那些废弃多年的数组映射、字典存储（如 `AppearanceSettingsPanel` 中的 `ColorGroups`）必须予以**物理抹除**。
* **底层数据结构的延期审计与脱敏**：
  为保持重构的安全边际，被裁减掉的功能（如透明度参数 `WindowOpacity`），在视图（XAML）层面不予声明与展现，但其在对应的 `ViewModel` 和序列化底层模型 `AppConfig` 中的参数定义暂时保留，确保现存的所有依赖链路不会因序列化对齐等原因意外中断，同时避免引入新的数据迁移问题。
* **归档“僵尸”代码**：针对那些不再被渲染树触及的调色板控制器（如 `ThemeColorEditorWindow` 和 `ColorPickerControl`），它们将被隔离并视为孤点死代码。

## 4. 预期架构收益
此战役落地后，效果堪称立竿见影：
1. **轻巧灵动**：预计可在一个迭代中，清剿掉设置系统中约 **4500 ~ 5000 行纯手搓的渲染代码死链**，极大改善模块冷读速表现，显著预防潜在内存溢出问题。
2. **纯真血统的 MVVM**：业务逻辑、用户设置的变更请求与界面控件的渲染生命周期完成彻底物理隔离。
3. **为 Pro 版卸下镣铐**：将来重新开发 Pro 版的复杂高级定制功能时，开发者只需在极为纯净、易读的 XAML 的骨架上引入高级组件挂载点即可，从此告别在几千行 C# 里艰难定位 UI `Margin` 间距修改的黑暗开发模式。
