## 核心任务排序 (为全部重构铺路)

根据最新指示，我们已剥离非核心的视图层表现（方案 A），全面聚焦于底层基础设施的“骨架重塑”。以下是基于《配置系统架构规约》梳理出的剩余执行顺序，任务已按强依赖关系进行先后编排：

### 阶段 1：路径集中管理与废弃功能拔除 (消除硬编码)
* [x] **引入 `IConfigPathProvider`**：
  * [x] 定义基础接口，并提供基于用户 BaseDirectory (默认 `./AppData/`) 的标准实现。
  * [x] 将其注册到 DI 容器供全局注入。
* [x] **收束零散路径硬编码**：
  * [x] 修复 `SearchHistoryService`、`CustomThemeManager` 中的路径硬编码，全盘替换为调用 `IConfigPathProvider`。
* [x] **彻底清理 TagTrain 遗留逻辑**：
  * [x] 在代码库中搜索并剔除 `tt_settings.txt`、`tt_training.db` 等无用导出/打包逻辑，为后续系统减负。

### 阶段 2：单体配置拆解与双文件架构落地
* [x] **拆解 `AppConfig` 单体大类**：
  * [x] 按照规约分为 `UserSettings` (主要包含外观、行为、偏好，对应 `yibofile_settings.json`) 与 `AppState` (包含窗体大小、布局留存、会话，对应 `yibofile_state.json`)。
* [x] **实现新格式的双路 JSON 读写通道**：
  * [x] 为 Settings 引入防抖 (Debounce) 自动保存，为 State 引入延迟保存 (Lazy Save) 机制。
* [x] **启动层无缝数据迁移策略 (`Migrator`)**：
  * [x] 编写启动迁移器，接管旧版 `ooi_config.json` 数据并安全分割迁移至新结构，之后产生 `.bak` 备份文件。
  * [x] 重命名底层数据库 `ooi_data.db` 为 `yibofile_data.db`。

### 阶段 3：废除静态单例，IConfigurationService 强依赖闭环
* [x] **合并历史配置管理器**：
  * [x] 将 `ConfigManager`（静态类）的所有核心 I/O 逻辑下沉融入 `ConfigurationService`。
* [x] **暴露纯粹的 `IConfigurationService` 接口**：
  * [x] 对外仅提供 `GetSetting/SetSetting`，`GetState/SetState` 以及持久化控制。
* [x] **切断全图单例调用**：
  * [x] 在原有 ViewModel 和底层类中寻找 `ConfigurationService.Instance` 调用，批量改写为通过构造函数依赖注入的形式，实现彻底的测试友好型架构。

### 阶段 4：配置与数据导出中心 (解耦散落的导出入口)
* [x] **构建 `IExportService` 与 `IImportService`**：
  * [x] 实现独立模块层级的导出能力：`组织结构` (库/收藏/标签定义 -> `structure.json`)、`文件元数据` (关联标签/备注 -> `filedata.json`)。
* [x] **打包机制与防冲突校验**：
  * [x] 实现支持分块导入的 Zip 读写，在架构层面解决路径缺失时的“映射/忽略/自动创建”冲突策略。
* [x] **收拢 UI 入口**：
  * [x] 建立集中的“导出中心”面板，取缔并移除现存各子面板中分布零散的导入/导出按钮。
