# YiboFile 地址协议与虚拟路径规范 (Address Protocol & Virtual Path Specification)

## 1. 概述 (Overview)

本文档旨在详述 **YiboFile** 系统内部使用的地址协议体系。通过引入统一资源标识符 (URI) 机制，系统将物理文件系统路径、压缩包内部路径、元数据筛选视图以及内部功能组件进行了高度抽象，从而实现了“路径平权”的交互逻辑。

---

## 2. 协议族定义 (Protocol Families)

系统根据资源性质将路径分为以下几类协议：

### 2.1 物理路径 (Physical Paths)

*   **隐含协议**: 无前缀或 `path:/`
*   **语法**: `[DRIVE]:\path\to\folder` 或 `\\Server\Share`
*   **示例**: `C:\Windows\System32`, `path:/D:\Workspace`
*   **行为**: 
    *   映射到 Windows 操作系统的物理存储位置。
    *   支持所有标准文件操作（新建、删除、重命名等）。
    *   在内部处理中，系统会自动将分号、斜杠进行归一化处理。

### 2.2 压缩包协议 (Archive Protocol)

*   **前缀**: `zip://`
*   **语法**: `zip://<Archive_File_Path>|<Internal_Path>`
*   **示例**: `zip://C:\Backup.zip|Project/Docs/manual.pdf`
*   **行为**: 
    *   使用 `|` 字符作为物理边界标识符。
    *   支持像浏览真实文件夹一样进入压缩包内部。
    *   在压缩包根目录执行“向上导航”时，将返回至该 `.zip` 文件所在的物理文件夹。

### 2.3 虚拟/系统协议 (Virtual Systems)

*   **前缀**: `yibofile://`
*   **语法**: `yibofile://<Component_ID>`
*   **典型组件**:
    *   `yibofile://Settings` — 设置主面板
    *   `yibofile://TaskQueue` — 后台任务与传输队列
    *   `yibofile://About` — 关于页面
*   **行为**: 
    *   不指向物理文件，而是指向特定的 UI 模块。
    *   通常在标签管理系统中作为“特殊标签页”存在。

### 2.4 文献/库协议 (Library Protocol)

*   **前缀**: `lib://`
*   **语法**: `lib://<Library_ID_or_Name>`
*   **示例**: `lib://Documents`, `lib://Music`, `lib://Pictures`
*   **行为**: 
    *   聚合视图协议。将分散在不同物理位置的文件聚合在同一逻辑视图下。
    *   不支持直接在该视图下通过物理手段创建文件夹。

### 2.5 标签协议 (Tag Protocol)

*   **前缀**: `tag://`
*   **语法**: `tag://<Tag_Name>`
*   **示例**: `tag://Important`, `tag://Project_Alpha`
*   **行为**: 
    *   基于元数据的筛选视图。显示所有被标记为该名称的文件列表。

### 2.6 搜索协议 (Search Protocols)

*   **前缀**: `search://` (文件名) 与 `content://` (全文)
*   **语法**: `search://<Query_String>`
*   **示例**: `search://ext:py size:>10kb`, `content://Antigravity`
*   **行为**: 
    *   动态生成的虚拟列表视图，展示搜索匹配项。

## 3. 技术实现要点 (Implementation Details)

### 3.1 核心解析器 (`ProtocolManager`)
系统通过 `ProtocolManager.cs` 进行路径解析。该类负责将字符串路径转换为 `ProtocolInfo` 对象，包含：
*   **Type**: 协议类型 (`Local`, `Archive`, `Search`, `Library` 等)。
*   **TargetPath**: 剥离协议头后的核心路径。
*   **ExtraData**: 扩展元数据（如压缩包的内部路径）。

### 3.2 路径归一化 (`NormalizePath`)
为保证多组件交互的一致性，系统在导航前会执行归一化：
1.  **斜杠统一**: 物理路径统一使用 `\`，虚拟路径协议头后保持 `/`。
2.  **盘符处理**: 确保盘符（如 `C:`）在物理路径中始终大写并带有结尾反斜杠。
3.  **协议检测**: 优先识别已知协议头，防止被误判为物理驱动器或 UNC 路径。

## 4. 后续扩展计划 (Future Roadmap)

*   **云盘协议**: 计划引入 `cloud://` 以支持 OneDrive/Dropbox 等集成。
*   **FTP/SFTP**: 引入 `ftp://` 与 `sftp://` 实现远程文件系统透明导航。
*   **临时空间**: 引入 `temp://` 或 `scratch://` 用于跨面板操作的中转区。
