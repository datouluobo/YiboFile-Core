# YiboFile 标签页内容架构规范 (TabContent Architecture Spec)

> **文档创建日期**: 2026-02-23
> **状态**: ✅ 方案已确认 → 待实施
> **方案**: 方案 C — ITabContent 接口 + TabContentRegistry 自注册工厂
> **影响范围**: Core / Pro / Ultra / 第三方插件

---

## 一、背景与目标

### 1.1 当前问题

应用中存在**三种完全不同的页面宿主机制**并存，导致代码冗余、行为不一致、扩展困难：

| 页面 | 当前实现方式 | 宿主位置 |
|------|------------|---------|
| **设置页** | `SettingsPanelControl` + `SettingsOverlayController` | Overlay Grid (ZIndex=5000), 覆盖列0~5行1~3 |
| **关于页** | `AboutPanelControl` | Overlay Grid (ZIndex=5000), 同上 |
| **路径/库/标签管理** | `NavigationSettingsWindow` (独立Window) | 模态对话框 `ShowDialog()` |
| **任务队列** | `TaskQueuePanel` | 列2~5行1~3 (ActiveSpecialPanel="Tasks") |
| **备份管理器** | `BackupBrowserControl` | 列2~5行1~3 (ActiveSpecialPanel="Backup") |
| **剪切板历史** | `ClipboardHistoryPanel` | 列2~5行1~3 (ActiveSpecialPanel="Clipboard") |

### 1.2 重构目标

将上述所有页面**统一为标签页**，在主栏打开（可手动移到副栏），要求：

1. ✅ 变成标签页，复用现有标签页基础设施（拖拽、固定、关闭、移至副栏）
2. ✅ 适应单/双栏布局
3. ✅ 页面内容自适应，不能出现水平滚动条
4. ✅ 支持 Pro/Ultra 版本扩展新标签页类型（无需修改 Core）
5. ✅ 支持第三方插件注册自定义标签页（通过 `IYiboFilePlugin` 体系）
6. ✅ 标签页切换性能优良（View 缓存，避免重建 `FileBrowserControl`）

## 二、方案选型记录

### 2.1 候选方案

| 方案 | 核心思路 | 最终结论 |
|------|---------|---------|
| **A: 扩展 TabType 枚举 + PaneContentHost switch** | 在 `TabType` 中新增枚举值，PaneContentHost 内 switch 路由 | ❌ 枚举是中心瓶颈，Pro/Ultra 无法扩展 |
| **B: NavigationMode 特殊面板** | 复用 `ActiveSpecialPanel` 机制 | ❌ 不满足"变成标签页"需求，不可移到副栏 |
| **C: ITabContent 接口 + 自注册工厂** | 定义 ITabContent 接口，字符串 ContentTypeId，TabContentRegistry | ✅ **最终选定** |
| **D: TabType 枚举 + DataTemplateSelector** | WPF 原生 DataTemplateSelector 路由 | ❌ TabType 枚举 Pro/Ultra 不可扩展，DataTemplate 缓存困难 |

### 2.2 选择方案 C 的核心理由

1. **Pro/Ultra 扩展兼容**：`ContentTypeId` 是字符串，任何层（Core/Pro/Ultra/第三方插件）都可以自由定义新 ID，无需修改 Core 代码
2. **性能优势**：`ITabContent.CreateView()` 天然支持 View 实例缓存，避免 `FileBrowserControl` 反复销毁重建（构造函数 ~80 行，重建约 15~30ms）
3. **切换动画支持**：显式的 `OnActivated()` / `OnDeactivated()` 生命周期回调支持入场/退场动画
4. **插件体系对齐**：新增 `ITabPageExtension` 与现有 `IMenuExtension`、`IPreviewExtension` 并列，完美融入插件架构
5. **未来需求覆盖**：可预见 ~19 种标签页类型 + 不可预知的第三方插件数量

## 三、架构设计

### 3.1 核心接口

```csharp
namespace YiboFile.Interfaces.Plugins
{
    /// <summary>
    /// 可承载于标签页的内容的统一抽象。
    /// 所有特殊标签页（设置、关于、管理、任务队列等）以及
    /// Pro/Ultra/第三方插件注册的自定义标签页均需实现此接口。
    /// </summary>
    public interface ITabContent
    {
        /// <summary>
        /// 内容类型唯一标识。
        /// Core 内置类型使用小写字母（如 "settings", "about", "tasks"）。
        /// 插件类型建议使用 "vendor.name" 格式（如 "yibofile.fts-results"）。
        /// </summary>
        string Id { get; }

        /// <summary>
        /// 标签页显示标题。
        /// </summary>
        string Title { get; }

        /// <summary>
        /// 图标资源键（引用 Icon Contract 中的键名）。
        /// </summary>
        string IconKey { get; }

        /// <summary>
        /// 是否允许同时打开多个同类型标签页。
        /// 例如：文件浏览 = true, 设置 = false。
        /// </summary>
        bool AllowMultiple { get; }

        /// <summary>
        /// 是否支持在副栏打开。
        /// 某些面板（如设置页）可能在窄副栏中体验不佳。
        /// </summary>
        bool SupportsSecondaryPane { get; }

        /// <summary>
        /// 创建或返回缓存的 View 实例。
        /// 实现者应在内部管理 View 的生命周期和缓存策略。
        /// 首次调用时创建，后续调用可返回缓存实例。
        /// </summary>
        UserControl CreateView();

        /// <summary>
        /// 标签页被激活时调用（切换到前台）。
        /// 用于恢复后台任务、刷新数据、播放入场动画等。
        /// </summary>
        void OnActivated();

        /// <summary>
        /// 标签页被切离时调用（切换到后台）。
        /// 用于暂停后台任务、保存临时状态、播放退场动画等。
        /// 注意：此时 View 不应被销毁（除非内存压力触发 LRU 回收）。
        /// </summary>
        void OnDeactivated();

        /// <summary>
        /// 标签页被关闭时调用（用户点击关闭按钮）。
        /// 用于释放资源、保存最终状态。
        /// </summary>
        void OnClosed();
    }
}
```

### 3.2 插件扩展接口

```csharp
namespace YiboFile.Interfaces.Plugins
{
    /// <summary>
    /// 标签页扩展接口。
    /// 插件通过实现此接口向应用注册自定义标签页类型。
    /// 与 IMenuExtension、IPreviewExtension 并列的第三种插件扩展点。
    /// </summary>
    public interface ITabPageExtension
    {
        /// <summary>
        /// 要注册的内容类型 ID。
        /// </summary>
        string ContentTypeId { get; }

        /// <summary>
        /// 创建 ITabContent 实例。
        /// </summary>
        ITabContent CreateContent();
    }
}
```

### 3.3 注册中心

```csharp
namespace YiboFile.Services.UI.Tabs
{
    /// <summary>
    /// 标签页内容注册中心。
    /// 管理所有 ITabContent 工厂的注册与解析。
    /// Core 内置类型在 Bootstrapper 中注册，
    /// Pro/Ultra 通过 DI 自动发现注册，
    /// 第三方插件通过 PluginManager 扫描 ITabPageExtension 注册。
    /// </summary>
    public class TabContentRegistry
    {
        private readonly Dictionary<string, Func<ITabContent>> _factories = new();

        /// <summary>
        /// 注册一个内容类型工厂。
        /// </summary>
        public void Register(string contentTypeId, Func<ITabContent> factory);

        /// <summary>
        /// 解析并创建指定类型的 ITabContent 实例。
        /// </summary>
        public ITabContent Resolve(string contentTypeId);

        /// <summary>
        /// 检查指定类型是否已注册。
        /// </summary>
        public bool IsRegistered(string contentTypeId);

        /// <summary>
        /// 获取所有已注册的内容类型 ID 及其元数据（用于构建"新建标签页"菜单）。
        /// </summary>
        public IReadOnlyList<TabContentMetadata> GetAll();
    }
}
```

### 3.5 PaneContentHost（新建 UserControl）

```
PaneContentHost 职责：
1. 监听当前活跃标签页的 ContentTypeId 变化
2. 根据 ContentTypeId 通过 TabContentRegistry 获取 ITabContent
3. 调用 ITabContent.CreateView() 获取 View
4. 在 ContentPresenter 中显示 View
5. 管理 OnActivated / OnDeactivated 生命周期调用
6. 维护 View 实例缓存（避免反复创建/销毁）

特殊处理：
- 文件浏览类标签（path/library/tag/search）：
  复用同一个 FileBrowserControl 实例，通过 DataContext 切换
- 特殊面板标签：每个 ITabContent 持有自己的 View 缓存
```

## 五、性能策略

### 5.1 View 缓存机制

```
ITabContent 实现者负责管理自己的 View 缓存：

1. 单例面板（AllowMultiple = false）：
   - 首次 CreateView() 创建实例
   - 后续 CreateView() 返回缓存
   - OnDeactivated() 时不销毁 View，仅暂停后台任务
   - OnClosed() 时释放资源

2. 文件浏览类面板（AllowMultiple = true）：
   - FileBrowserTabContent 包装 FileBrowserControl
   - 同一标签页的 ITabContent 实例与其 View 一一绑定
   - 切换标签页时通过 DataContext 切换数据源
   - PaneContentHost 维护 LRU 缓存池（最多保留 N 个非活跃 View）

3. LRU 回收策略：
   - 当非活跃标签页数量超过阈值（建议 5~8），触发最久未访问的 View 释放
   - 释放前调用 ITabContent.OnDeactivated()
   - 下次激活时重新调用 CreateView() 重建
```

### 5.2 标签切换性能目标

| 操作 | 目标时间 | 手段 |
|------|---------|------|
| 相同类型标签切换 (Path → Path) | < 50ms | DataContext 切换，不重建 View |
| 不同类型标签切换 (Path → Settings) | < 100ms | View 缓存命中，仅切换可见性 |
| 首次打开特殊标签 | < 200ms | 延迟加载，CreateView() 按需执行 |
| 特殊标签 View 被 LRU 回收后重建 | < 300ms | 重新 CreateView()，可接受 |

### 5.3 切换动画策略

```
PaneContentHost 切换逻辑：

1. 旧 Tab 的 ITabContent.OnDeactivated() → 可触发退场动画
2. 新 Tab 的 ITabContent.CreateView() → 获取 View
3. ContentPresenter 切换内容
4. 新 Tab 的 ITabContent.OnActivated() → 触发入场动画

推荐动画：
- 入场：Opacity 0→1 + TranslateY 20→0, Duration=200ms, EaseOut
- 退场：Opacity 1→0, Duration=100ms (可选,若性能允许)
```

## 六、响应式布局规范

### 6.1 通用原则

所有标签页内容**必须**遵循：

1. **禁止固定宽度**：移除所有 `MinWidth`（或设为合理最小值如 `MinWidth="300"`）
2. **禁止水平滚动**：`HorizontalScrollBarVisibility="Disabled"`
3. **使用自适应列宽**：内部 Grid 使用 `Width="*"` 和 `Width="Auto"`
4. **纵向可滚动**：内容超出时使用 `ScrollViewer` 纵向滚动

### 6.2 各面板适配要点

| 面板 | 改造要点 |
|------|---------|
| **设置页** | 移除 `MinWidth="800"`；左导航改为 `Width="Auto" MinWidth="140" MaxWidth="200"`；移除关闭按钮（标签页提供关闭） |
| **关于页** | 移除 `MinWidth="600"`；左导航同上；移除关闭按钮 |
| **管理页** | 新建时直接按自适应设计 |
| **备份管理器** | 三列布局改为：左列 `Width="Auto" MinWidth="160"`，中列 `Width="*"`，右列预览 `Width="Auto" MinWidth="200"`；窄宽度时触发 DataTrigger 折叠预览列 |
| **任务队列** | 移除浮动卡片样式（CornerRadius、DropShadow）；移除拖拽逻辑；改为全宽布局 |
| **剪切板历史** | 移除固定 320px 宽度；改为全宽列表布局 |

### 6.3 宽度适应矩阵

| 场景 | 可用宽度 | 行为 |
|------|---------|------|
| **单栏 (Full)** | ~700px+ | 完整布局（左导航 + 右内容）|
| **单栏 (Focus)** | ~960px+ | 完整布局 |
| **双栏-主栏** | ~450px+ | 压缩布局（左导航缩至 MinWidth 或折叠）|
| **双栏-副栏** | ~360px | 紧凑布局（左导航折叠为图标栏，或切换为顶部导航）|

## 九、与其他系统的交互约定

### 9.1 与消息总线的交互

新增消息：

| 消息 | 用途 |
|------|------|
| `OpenContentTabMessage { ContentTypeId, TargetPane? }` | 请求打开指定类型的标签页 |
| `ClipboardPasteRequestMessage { Item }` | 剪切板面板选择粘贴时发布，替代直接事件 |

### 9.2 与标签页系统的交互

- `TabService.CreateSpecialTab(string contentTypeId)` — 创建特殊标签页，确保唯一性（`AllowMultiple=false` 时先查找已有标签）
- `TabService.SetActiveTab(tab)` — 切换时触发 `PaneContentHost` 的内容路由
- `PathTab.ContentTypeId` — 标签页数据模型中标识内容类型

### 9.3 与插件系统的交互

`PluginManager.LoadPluginsAsync()` 执行后：
1. 扫描所有 `ITabPageExtension` 实现
2. 调用 `TabContentRegistry.Register(ext.ContentTypeId, () => ext.CreateContent())`
3. 发布 `PluginTabRegisteredMessage` 通知 UI 更新菜单
